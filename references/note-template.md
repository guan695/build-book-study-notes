# 通用学习笔记规则

笔记不套固定目录，但必须让目标学习者达到本模块约定的能力，而不是只得到概览。标题之后先用几句话说明本模块解决什么问题、需要哪些先备知识、学完能做什么；正文按知识本身的依赖关系自由组织。

不同知识类型至少承担这些学习功能：

- 数学或技术主题：讲清假设、定义、符号、概念关系和推理或推导；给出至少一个不跳关键步骤、可独立复算的代表性例子；按需要说明边界、反例、易错点，并用练习和答案检查约定能力。
- 操作或方法主题：讲清原理、步骤、选择依据，给出完整演示，并说明常见失败与排查方法。
- 概念或历史主题：讲清背景、核心观点、证据、因果或比较关系，并用问题检查是否真正理解。

不要为了形式强塞无关小节，也不要把上述必要学习功能省略成术语清单。新概念必须建立在已经解释的内容上；较长主题宁可拆成下一篇，也不要跳过关键推理。

## Markdown 数学格式

- 所有数学变量、集合、运算符、关系符、箭头、希腊字母、上下标和公式都写在 LaTeX 数学环境中。
- 行内公式使用 `$...$`，例如 `$x \in \mathbb{R}^n$`。
- 独立公式使用单独成行的 `$$...$$`，例如：

  $$
  A\mathbf{x}=\mathbf{b}
  $$

- 多行推导在 `$$...$$` 内使用 `\begin{aligned}...\end{aligned}`；矩阵使用 `\begin{bmatrix}...\end{bmatrix}`。
- 使用 `\frac`、`\sum`、`\operatorname`、`\mathbf`、`\mathbb` 等标准命令。不要在正文中裸写 `∈`、`→`、`≤`、`×`、`α` 等 Unicode 数学符号，分别写成 `$\in$`、`$\to$`、`$\le$`、`$\times$`、`$\alpha$`。
- 不要把公式放进代码块。每个符号第一次出现时都要解释；交付前检查 Markdown 渲染结果，并对照原 PDF 核对公式。

## 来源

正文只依据实际阅读的本地小 PDF。末尾保留简短来源，不写检索过程、哈希或内部清单：

```markdown
## 来源

- B01 — *原书名*：[本地原书](../materials/B01-title.pdf)，[本次页段](../extracts/M01-B01-S01.pdf)。
```

只列本模块真正使用的原书和页段；补充书只用于填补主来源的具体缺口。
